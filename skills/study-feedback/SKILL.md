# 伴学反馈诊断与提报

采集 `study` 伴学过程中的真实失真现场，生成脱敏诊断单并按需外发给维护者。仅在用户显式输入 `/study-feedback` 时启动；未显式输入该命令的新会话或日常追问一律不调用本技能。

## 诊断出单规程

**终点**：已回扫当前伴学会话并对照 `../study/SKILL.md` 生成脱敏的五要素诊断单，按 `gh` 探测结果与用户选择完成提交或保留代码块，单轮结束且不改 `study` 文件。

- **版本提示**：同级存在 `../study/scripts/check_update.py` 时，结束前可顺带运行 `uv run ../study/scripts/check_update.py --passive`；有新版则在末尾用一行告知版本号与对应升级命令，绝不自动覆盖本地文件。
- **回扫现场**：附有口头说明时结合上下文定位对应伴学环节；零打字调用时自动回扫当前会话，定位用户纠偏、喊停、嫌分卡过碎过粗、嫌摸底跑偏或反复追问才搞通的位置。若长会话存在多处明显卡顿且定位不唯一，先用一句列出候选现场请用户点选确认，不自行脑补失真根因。空白会话且无伴学上下文时，如实告知无可提取记录，不编造条目。
- **强制脱敏**：严禁摘抄用户的未发表公式参数、私有业务代码、文件路径或商业数据；一律抽象还原为通用表征形态、代码行数规模与数学耦合结构。
- **规程对账**：同级存在 `../study/SKILL.md` 时读取主干及本次已加载的子文件，核查失真根因并做四选一定性：`A-已有条文漏执行`、`B-现行条文歧义冲突`、`C-未覆盖的新盲区`、`D-绘图脚本报错`；未挂载同级 `study` 源码时仅凭当前会话上下文出单并标待核。
- **诊断格式**：每条反馈统一生成以下五要素紧凑块：

```markdown
### [YYYY-MM-DD] 一句话问题标题
- **运行现场**：`<模型与思考档位>` ｜ `<靶向直答 / 分卡伴学·深度档>` ｜ 已读 `<表征文件名>` ｜ `<卡XX·第N轮>`
- **材料结构**：`<脱敏后的体裁、规模与数学/代码耦合特征>`
- **失真现场**：`<当时 AI 实际动作 → 卡住用户哪一步 → 用户如何纠偏跑通>`
- **规程定性**：`<A-已有条文漏执行 / B-现行条文歧义冲突 / C-未覆盖的新盲区 / D-绘图脚本报错>`；关联 `<小节或函数名>`
- **期望机制**：`<剥离单题细节后，期望规程或脚本怎么改的一句话描述>`
```

- **外发收口**：生成诊断单后按以下四步收口，未获用户明确同意不得静默外发：
  1. **先出单**：将上述诊断块包在 Markdown 代码块内输出，提醒用户核对标题与正文未含涉密代号或未发表专有参数。
  2. **只读探测**：静默运行 `python "<本技能目录>/scripts/submit_feedback.py" --probe` 探测 `gh` 安装与登录状态；无系统 Python 时改用 `python3` 或 `uv run --project "../study/scripts" python ...` 兜底。
  3. **用户选路**：推荐将邮箱项放首位，并简要说明点选一下即可自动发送、免登录免配置。`gh` 可用且已登录时三选一：① 推送到维护者邮箱（推荐：点选即自动发出）；② 一键提交到 `crrisugi/study-skill` GitHub Issue；③ 仅保留当前代码块。否则二选一：① 推送到维护者邮箱（推荐：点选即自动发出）；② 仅保留代码块并附 `https://github.com/crrisugi/study-skill/issues/new` 供手动提交。
  4. **通道执行**：经用户同意后，将脱敏诊断单写入系统临时文件，运行 `python "<本技能目录>/scripts/submit_feedback.py" --channel github|email --title "<一句话问题标题>" --body-file "<临时文件路径>" --delete-body-file`；无系统 Python 时改用 `python3` 或 `uv run` 兜底，成功告知结果或链接，环境缺失或外发失败时保留代码块兜底。
