# 伴学落盘细则与产出文档模板

由主干 [SKILL.md](../SKILL.md) 在写入 `00_伴学脉络蓝图.md` 或确认单卡落盘、合并总卡时按需加载；纯会话伴读与常规对话推演不读本文件。

---

## 一、落盘与验收细则

- **沿用对话顺推底稿**：落盘笔记面向日后独立阅读，直接以对话里已讲顺的推演为底稿做轻整理，保留关键展开式、具体算例、数值小表与配图，不压扁成干巴巴的提纲，也不把同一算例拆成两头重复写。
- **剥离对话互动痕迹**：删去开局路线表、摸底选择题与答题记录、试错闲话、`k-A / k-B` 中间停顿语、卡末心算自核问句及“顺了吗 / 回落盘”等交互语；仅当用户追问心算变化并算出有启发的新结论时，才把结论自然融进正文或易混处。
- **合并慢嚼与追问补讲**：分 `k-A / k-B` 两步慢嚼的复杂卡合写成同一张连贯讲义；对话中途的追问解释与卡壳后换路讲通的直白小例子自然揉进对应小节，不写成一问一答聊天体，删去前面绕弯的旧讲法。
- **摸底成果无痕融入**：本卡内顺手补讲的新符号画面与轻铺垫直接留在正文对应小节，不提因摸底补讲；摸底答错踩坑的易混点无痕收进结尾易混处并优先讲透；答对跳过的基础不单辟前置框，靠正文用到时顺手写清关键算式保持独立可读。
- **顺手自查不漏项**：不套带黑括号的列表外壳，改用 `##` 自然人话小标题、短段落与居中大公式；落盘前自查五项是否落入正文——开头问题与核心对象、最小算例推通原式、加粗核心结论、量纲/维度/状态核对、得失与前提/易混处；对话偶发漏写某句时顺手补入对应小节。
- **速通落盘形态**：单块材料 `直觉速通` 合并写 `01_全篇脉络总卡.md` 时，按各节内容用自然 `##` 小标题串起核心结论、直观小例与配图，末尾单设自然小节统一记权衡与成立前提；总图 `直觉速通` 分节短卡按 [long-corpus.md](long-corpus.md) 用 `2~3` 个自然 `##` 小标题逐卡落盘。
- **配图与正文纯净**：笔记内配图统一写相对路径 `![图注](assets/卡XX_图名.<后缀>)`，不把 `<agent-embed>` 写入 `.md`，也不在对话框重复贴整卡正文；遵循主干 `引用直写算式` 规则，正文、小标题与配图均不夹带原件公式号、章节号或附录索引。
- **落盘校验**：带图单卡落盘后跑单文件体检，写工作区文件且末卡结课前跑整目录验收，执行 `python "<本技能目录>/scripts/check_notes.py" "<目标路径>"`；无系统 Python 时改用 `uv run --project "<本技能目录>/scripts" python ...` 兜底，修完报错再宣布归档或结课；纯文字中间卡与纯会话伴读免跑。

## 产出文档模板

### 1. 开局脉络文件模板（`00_伴学脉络蓝图.md`）

```markdown
# 00｜学习脉络：[用一句平实人话概括这份材料要搞懂什么]

> **学习材料**：[原图/论文/代码文件名或链接] ｜ **默认深度**：[直觉速通 / 标准推演 / 深度精读]

## 一、这次学什么、哪些底层前提先直接拿来用
- **核心问题**：（用两三句大白话说清这份材料整体在解决什么表达、建模、算法或选型问题）
- **先直接拿来用的前提**：（对原材料未展开的底层推导或外部模块，每项只用一句大白话交代“它输入什么、给我们什么结果”，正文直接当已知底座用）

## 二、卡片学习顺序（从简到繁共 X 张；同卡拆多机制用 01.1 / 01.2，卡前先修用 目标卡号_0.1 / _0.2）
| 顺序 | 卡片主题（括注原位置或“先修铺垫”；核心推导卡括注“核心”） | 这一步主要搞懂什么 |
| :--- | :--- | :--- |
| 卡 01 | ... | （用一句平实白话说清这一张卡解决什么问题、比上一张多了什么） |
| 卡 02 | ... | ... |

## 三、底座算例设定
- **最小输入与范围设定**：（连贯推导列全篇共用的一套最小输入，并列独立主题按组或按卡各自列；多源对照材料可在此附简短的《跨文档符号/变量对照表》）
- **代入的具体数值**：（写明各卡用来算账对比的具体小整数、简单基函数或初始状态）
```

### 2. 单张学习笔记卡骨架示例（`卡XX_[概念名称].md`）

直接沿用对话小标题或按本卡内容自由起 `##` 人话小标题，小节数量按需增减，绝不照抄方括号占位说明，也不套带黑括号的列表外壳：

```markdown
# 卡 XX｜[概念名称]（原位置：xxx；先修卡写“先修铺垫”）

## [随内容起的人话小标题：引出问题与核心对象]
（两三句短陈述句说清要解决什么问题或老办法卡在哪；需用到的核心算式或关键代码居中写全）

## [随内容起的人话小标题：最小算例推通原式]
（按对话讲顺的顺序保留关键展开步、具体算例验算与量纲/维度/状态核对，大公式居中占行；小表与 `![图注](assets/卡XX_图名.<后缀>)` 紧贴对应段落下方；可按内容拆为 2~3 个自然小节，不把同一算例写两遍）

**核心结论：[用一两句直白短话加粗收束本卡核心结论]**

## [随内容起的人话小标题：得失、成立前提与容易踩的坑]
- （写清这步变形或做法换来什么好处、付出什么代价；紧扣本卡范围写出成立前提与易混处，摸底踩过的误区优先讲透，有 `1` 条写 `1` 条，不凑数）
```
